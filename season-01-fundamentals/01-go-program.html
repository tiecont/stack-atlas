Một chương trình Go thực sự là gì?

Từ file .go, package main đến binary: mental model đầu tiên trước khi học syntax.

1. Mental model

Khi mới học Go, nhiều người bắt đầu bằng cách ghi nhớ cú pháp. Cách dễ hơn là hiểu một chương trình Go đi qua những lớp nào: source code thuộc một package, package thuộc một module, toolchain kiểm tra và biên dịch code, cuối cùng tạo ra executable hoặc library package.

Go được thiết kế để vòng lặp “viết → format → test → build” rất ngắn. Bạn nên làm quen với các lệnh chuẩn ngay từ ngày đầu thay vì phụ thuộc vào IDE.

2. Code đầu tiên

Gopackage main

import "fmt"

func main() {
    fmt.Println("Hello, Go")
}

3. Hiểu sâu hơn

`package main` nói rằng package này có thể tạo executable. Hàm `main` là entry point của executable đó. `import "fmt"` đưa package chuẩn `fmt` vào phạm vi sử dụng.

Chạy bằng `go run .` tiện khi học; build bằng `go build` giúp bạn thấy một đặc tính quan trọng của Go: chương trình thường được phát hành như một binary đã biên dịch.

Examplego mod init example.com/hello
go fmt ./...
go test ./...
go build ./...
go run .

4. Khi đặt vào backend thật

Trong backend, mental model này giúp bạn hiểu tại sao container Go thường rất gọn: build stage chứa toolchain, runtime image chỉ cần binary và những file runtime thực sự cần. Nó cũng giải thích vì sao lỗi compile-time được phát hiện sớm hơn nhiều lỗi kiểu động.

Câu hỏi nên tự hỏiKhi concept này đi qua HTTP, database, cache hoặc worker, ownership nằm ở đâu, lifecycle kết thúc khi nào, và failure được biểu diễn ra sao?

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Nhầm package với folder theo nghĩa tuyệt đối; package là đơn vị code, folder là cách tổ chức source phổ biến.
  • Dùng `go run file.go` cho project nhiều file rồi tưởng các file khác “không được nhận”. Hãy dùng `go run .`.
  • Không chạy `gofmt`/`go fmt`; Go cố tình chuẩn hóa format để giảm tranh luận style.

Điều cần mang sang bài tiếp theo

  • Package là đơn vị biên dịch và namespace quan trọng.
  • Module là đơn vị version/dependency ở cấp project.
  • Toolchain chuẩn là một phần rất lớn của trải nghiệm Go.
