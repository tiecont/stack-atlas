HTTP/2: Multiplexing và Connection Behavior

Hiểu stream, multiplexing và những gì Go net/http tự làm cho bạn.

HTTP/2 thay đổi cách nhiều request dùng một connection. Thay vì nghĩ “mỗi request cần một TCP connection”, hãy nghĩ nhiều logical streams có thể multiplex trên cùng connection.

1. Stream là logical request/response channel

Các frame của nhiều streams có thể xen kẽ trên cùng connection. Điều này giúp concurrency tốt hơn ở tầng protocol nhưng không loại bỏ mọi dạng head-of-line blocking vì TCP phía dưới vẫn là ordered stream.

2. Go 1.27 và net/http

Ở Go 1.27, HTTP/2 implementation nằm trong standard library net/http; tài liệu hiện tại cũng cung cấp cấu hình protocol/HTTP2 trực tiếp trên Server và Transport. Phần lớn application không cần import x/net/http2 trực tiếp.

Đừng hard-code assumption cũHTTP stack của Go tiến hóa theo version. Khi tuning HTTP/2, hãy đọc docs đúng version toolchain của bạn thay vì dựa vào bài viết cũ.

3. Pool sizing thay đổi mental model

Trong HTTP/1.1, nhiều concurrent requests thường cần nhiều connections per host. HTTP/2 cho phép nhiều streams cùng connection, nên “50 concurrent request = 50 TCP connections” không còn là assumption đúng.

4. Quan sát protocol thật sự được negotiate

goresp, err := client.Do(req)
if err != nil { return err }
fmt.Println(resp.Proto) // ví dụ HTTP/2.0

Khi benchmark, xác nhận protocol version trước khi diễn giải connection count hoặc latency.
