Bài cuối Season 07 biến cache từ một lệnh GET/SET thành một subsystem có lifecycle và metrics. Mục tiêu là tăng performance mà vẫn giữ failure blast radius có kiểm soát.

2. Checklist

  • Key namespace/version rõ.
  • TTL + jitter.
  • Negative cache nơi phù hợp.
  • Singleflight cho hot miss.
  • DB remains source of truth.
  • Redis timeout nhỏ hơn request budget.
  • Metrics hit/miss/latency/error.

3. Load test

Test cả warm cache, cold cache, hot key và Redis unavailable. Chỉ benchmark happy-path hit sẽ bỏ qua failure mode quan trọng nhất.

4. Khi nào bỏ cache?

Nếu DB query đã rất nhanh, load thấp và data freshness khó đảm bảo, bỏ cache có thể là kiến trúc tốt hơn.

Điểm cần nhớ

  • Cache là performance subsystem với consistency cost.
  • Test cold path và outage path.
  • Đừng cache nếu chưa có bottleneck hoặc requirement rõ.
