Cache-aside đơn giản vì database vẫn độc lập với cache. Nhưng chính application phải chịu trách nhiệm cho miss path và invalidation.

1. Read path

2. Code skeleton

gofunc (s *Service) GetUser(ctx context.Context, id int64) (User, error) {
    if u, ok := s.cache.Get(ctx, id); ok {
        return u, nil
    }
    u, err := s.repo.Get(ctx, id)
    if err != nil { return User{}, err }
    _ = s.cache.Set(ctx, u, 5*time.Minute)
    return u, nil
}

3. Write path

Common strategy là update DB trước rồi delete cache. Delete thường an toàn hơn cố update cache vì cache representation có thể khác source.

4. Cache failure

Nếu Redis unavailable, nhiều hệ thống chọn fallback DB. Nhưng fallback phải bounded; nếu toàn bộ traffic cache miss cùng lúc, database có thể overload.

Điểm cần nhớ

  • Cache-aside giữ DB là source of truth.
  • Miss path phải chịu được concurrency.
  • Cache outage có thể biến thành DB outage.
