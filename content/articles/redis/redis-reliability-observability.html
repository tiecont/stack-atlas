Redis nhanh khi khỏe, vì vậy application rất dễ vô tình phụ thuộc mạnh vào nó. Production design cần định nghĩa Redis failure có làm request fail hay chỉ degrade.

1. Timeout ngắn và rõ

Cache thường nằm trước database nên timeout của cache nên đủ ngắn để còn budget fallback. Không để một Redis call chậm ăn hết request deadline.

2. Memory và eviction

Khi memory đầy, behavior phụ thuộc maxmemory policy. Eviction rate tăng thường là dấu hiệu working set vượt capacity.

3. Metrics

4. Persistence ≠ cache correctness

Redis có persistence/replication options, nhưng nếu role của Redis chỉ là rebuildable cache, app vẫn nên chịu được data loss của cache.

Điểm cần nhớ

  • Cache timeout phải nằm trong request budget.
  • Theo dõi effectiveness và saturation.
  • Failure policy phải explicit: fail-open hay fail-closed theo use case.
