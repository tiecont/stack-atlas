1. Race Condition là gì?

Race condition xuất hiện khi kết quả của chương trình phụ thuộc vào thứ tự hoặc timing mà nhiều goroutine truy cập cùng một state.

Govar counter int

go func() { counter++ }()
go func() { counter++ }()

2. Một bug phụ thuộc timing

counter++ trông như một bước, nhưng về mặt logic nó gồm đọc, tăng và ghi lại. Hai goroutine có thể cùng đọc giá trị cũ rồi ghi đè kết quả của nhau.

TimelineA: read counter = 0
B: read counter = 0
A: write 1
B: write 1

Expected: 2
Possible: 1
Điểm nguy hiểmRace thường biến mất khi bạn thêm log hoặc debug, vì chính việc debug làm timing thay đổi.

3. Dùng Go Race Detector

Go có race detector tích hợp. Khi test hoặc chạy app, bật nó để tìm những vùng memory đang bị truy cập không an toàn.

Terminalgo test -race ./...
go run -race ./cmd/server

Race detector rất hữu ích trong CI, nhưng không thay thế thiết kế synchronization đúng.

4. Fix bằng synchronization hoặc ownership

Có ba hướng quen thuộc: dùng mutex để bảo vệ critical section, dùng atomic cho cập nhật nhỏ, hoặc thay đổi ownership để chỉ một goroutine được phép sửa state và các goroutine khác gửi message.
