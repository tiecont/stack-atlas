1. Mental model

Go là ngôn ngữ statically typed, nhưng phần lớn code không cần viết type ở mọi nơi vì compiler có thể suy luận từ biểu thức khởi tạo. Điều đáng học hơn cú pháp khai báo là khái niệm zero value: biến luôn có một giá trị hợp lệ của type ngay cả khi bạn chưa gán thủ công.

Zero value giảm số trạng thái “chưa khởi tạo” mà developer phải quản lý, nhưng không có nghĩa zero value luôn có semantics đúng với domain của bạn.

3. Hiểu sâu hơn

Các type cơ bản như integer, floating point, boolean và string có zero value dễ đoán. Với pointer, slice, map, channel, function và interface, zero value thường là `nil`. Một số nil value vẫn dùng được cho một số operation, một số thì không.

`:=` chỉ dùng trong function body và tạo ít nhất một biến mới. `const` là constant ở compile time; constant trong Go còn có cơ chế “untyped constant” giúp biểu thức số linh hoạt hơn trước khi bị ép vào một concrete type.

4. Khi đặt vào backend thật

Trong config/backend model, zero value rất quan trọng. Ví dụ `Timeout time.Duration` bằng `0` có thể được hiểu là “không timeout”, “dùng default”, hoặc “invalid”. Hãy quyết định semantics rõ ràng thay vì để zero value vô tình mang nhiều nghĩa.

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Dùng `int` cho ID hoặc dữ liệu wire mà không cân nhắc kích thước/semantics.
  • Nhầm `nil` slice với empty slice khi serialize JSON; tùy encoder và contract chúng có thể khác nhau.
  • Dùng zero value để biểu diễn “không được cung cấp” khi domain cũng cho phép chính giá trị zero.

Điều cần mang sang bài tiếp theo

  • Zero value là một phần của API design trong Go.
  • Type rõ ràng giúp compiler bắt lỗi trước runtime.
  • Đừng chỉ hỏi “type nào compile được”; hãy hỏi “type nào diễn đạt domain tốt nhất”.
