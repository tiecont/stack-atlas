1. Mutex làm gì?

sync.Mutex biến một vùng code thành nơi chỉ một goroutine được đi vào tại một thời điểm.

Govar mu sync.Mutex
var counter int

mu.Lock()
counter++
mu.Unlock()

2. Critical section

Phần code nằm giữa Lock() và Unlock() là critical section. Giữ nó càng nhỏ càng tốt: đừng gọi network, sleep hay làm việc nặng trong lúc giữ lock nếu không cần thiết.

Gomu.Lock()
value := cache[key]
mu.Unlock()

// làm việc chậm ở ngoài lock
process(value)

3. defer Unlock

Pattern rất phổ biến là lock rồi defer unlock ngay bên cạnh để tránh quên unlock khi function return sớm.

Gofunc (s *Store) Get(key string) string {
    s.mu.Lock()
    defer s.mu.Unlock()
    return s.data[key]
}

4. Không copy một Mutex đang dùng

sync.Mutex chứa state nội bộ. Đừng copy struct có mutex sau khi nó đã bắt đầu được sử dụng; thường type sở hữu mutex nên được truyền bằng pointer.

Gotype Store struct {
    mu   sync.Mutex
    data map[string]string
}

func (s *Store) Put(k, v string) { ... }

5. Mutex hay Channel?

HeuristicNếu nhiều goroutine cần đọc/ghi cùng một state nhỏ, mutex thường đơn giản. Nếu vấn đề là truyền ownership, pipeline hay producer/consumer, channel thường tự nhiên hơn.
