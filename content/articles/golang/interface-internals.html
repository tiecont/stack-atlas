1. Mental model

Một interface value có thể được hiểu bằng hai thành phần logic: dynamic type và dynamic value. Interface chỉ bằng nil khi cả hai không có value/type động phù hợp. Đây là nguồn của typed-nil pitfall.

Exact in-memory words/layout là implementation detail; mental model type + value đủ để reasoning correctness.

Runtime noteNội dung runtime được viết theo Go 1.27 hiện hành. Các chi tiết implementation có thể thay đổi; language/spec behavior mới là contract ổn định.

2. Code đầu tiên

Gotype MyError struct{}
func (*MyError) Error() string { return "boom" }

func f() error {
    var e *MyError = nil
    return e // interface has dynamic type *MyError
}

3. Hiểu sâu hơn

Caller nhận `error` có thể thấy `err != nil` vì interface mang dynamic type dù pointer bên trong nil. Cách tốt nhất là đừng return typed nil như một non-nil interface value.

Assign concrete value vào interface đôi khi liên quan boxing/copy/allocation, nhưng compiler có nhiều optimization; hãy dùng benchmark/escape analysis nếu performance quan trọng.

Examplefunc f() error {
    var e *MyError
    if e == nil { return nil }
    return e
}

4. Khi đặt vào backend thật

Typed nil thường xuất hiện trong custom error/repository abstraction. Review API để return literal `nil` khi không có lỗi, và viết test cho boundary này.

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Return typed nil pointer dưới dạng `error`.
  • Dùng reflection chỉ để “fix” nil confusion.
  • Tối ưu boxing dựa vào giả định runtime layout cố định.

Điều cần mang sang bài tiếp theo

  • Interface nil là câu chuyện dynamic type + dynamic value.
  • Typed nil là correctness pitfall trước khi là runtime topic.
  • Không phụ thuộc exact interface layout trong application code.
