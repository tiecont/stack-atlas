1. Mental model

Go cho phép gắn method vào named type bằng receiver. Lựa chọn value receiver hay pointer receiver không nên bắt đầu từ câu “cái nào nhanh hơn”, mà từ semantics: method có mutate receiver không, type có identity không, copy có hợp lý không.

Pointer trong Go cho phép tham chiếu đến value khác nhưng không có pointer arithmetic thông thường như C.

2. Code đầu tiên

Gotype Counter struct { n int }

func (c *Counter) Inc() {
    c.n++
}

func (c Counter) Value() int {
    return c.n
}

3. Hiểu sâu hơn

Pointer receiver có thể mutate value được trỏ tới và tránh copy receiver lớn. Value receiver làm việc trên copy của value, phù hợp với immutable-ish small value types. Method set cũng ảnh hưởng việc một type có satisfy interface hay không.

Compiler thường tự thêm lấy địa chỉ/dereference trong method call đơn giản, nhưng interface satisfaction vẫn tuân theo method set.

4. Khi đặt vào backend thật

Service/repository thường có pointer receiver vì giữ dependency và identity của object. Value object nhỏ như `Money` hoặc custom enum có thể hợp lý với value receiver nếu method không mutate state.

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Dùng pointer receiver khắp nơi chỉ vì thói quen.
  • Dùng value receiver cho type lớn rồi copy liên tục.
  • Không hiểu method set dẫn đến “T does not implement Interface (method has pointer receiver)”.

Điều cần mang sang bài tiếp theo

  • Chọn receiver theo semantics trước micro-optimization.
  • Pointer receiver thường dùng khi mutate hoặc type có identity.
  • Method set là kiến thức nền cho interface.
