1. Mental model

Go cố tình có ít control-flow construct. Không có `while`; một từ khóa `for` bao phủ loop truyền thống, while-style loop và range loop. Sự đơn giản này khiến code backend của nhiều team trông khá giống nhau.

Functions trong Go đặc biệt quan trọng vì nhiều API trả về `(value, error)`. Đó không chỉ là syntax mà là cách control flow lỗi được làm rõ tại call site.

2. Code đầu tiên

Gofunc findUser(id int64) (User, error) {
    if id <= 0 {
        return User{}, errors.New("invalid id")
    }

    user, err := repo.Get(id)
    if err != nil {
        return User{}, err
    }
    return user, nil
}

3. Hiểu sâu hơn

`if` có thể có short statement trước condition, rất thường thấy với `if err := do(); err != nil`. `switch` trong Go không tự fallthrough mặc định. `for range` làm việc với nhiều collection nhưng bạn cần hiểu giá trị nó trả về cho từng type.

Multiple return values thường được dùng cho result + status/error. Named return values có chỗ dùng, nhưng nếu làm function dài khó đọc hơn thì không đáng.

4. Khi đặt vào backend thật

Một handler tốt thường là chuỗi decision rõ ràng: validate → gọi service → map error → response. Go khuyến khích early return, nên happy path ít bị lồng nhiều tầng `if`. Đây là một style rất hợp với backend code.

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Lồng `if` quá sâu thay vì early return.
  • Dùng `panic` như exception cho lỗi nghiệp vụ thông thường.
  • Viết function vừa query DB, gọi HTTP, format response và log mọi thứ — khó test và khó reuse.

Điều cần mang sang bài tiếp theo

  • Go ưu tiên control flow tường minh.
  • Multiple return values là nền tảng của error handling.
  • Function nhỏ với dependency rõ ràng dễ test hơn function “thông minh”.
