1. Mental model

Interface trong Go được implement ngầm: type không cần khai báo “implements”. Điều này đảo cách thiết kế quen thuộc từ nhiều ngôn ngữ OOP — interface thường nên được định nghĩa gần nơi sử dụng, theo behavior mà caller thật sự cần.

Một interface tốt thường nhỏ. `io.Reader` chỉ cần một method nhưng trở thành abstraction cực kỳ mạnh.

2. Code đầu tiên

Gotype UserFinder interface {
    FindByID(ctx context.Context, id string) (User, error)
}

type Service struct {
    users UserFinder
}

3. Hiểu sâu hơn

Implicit implementation giúp implementation không phụ thuộc package consumer chỉ để “đăng ký” interface. Bạn có thể thay database repo bằng fake trong test miễn satisfy behavior.

Interface value có cả dynamic type và dynamic value. Vì vậy “typed nil inside interface” là một pitfall nổi tiếng: interface có thể khác nil dù value bên trong là nil pointer.

Exampletype Reader interface {
    Read(p []byte) (n int, err error)
}

4. Khi đặt vào backend thật

Hãy tạo interface ở boundary có nhiều implementation hoặc cần test seam. Đừng tạo interface cho mọi struct ngay lập tức. Concrete types đơn giản thường dễ đọc hơn cho đến khi abstraction thực sự cần thiết.

Câu hỏi nên tự hỏiKhi concept này đi qua HTTP, database, cache hoặc worker, ownership nằm ở đâu, lifecycle kết thúc khi nào, và failure được biểu diễn ra sao?

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Interface “God object” có 20 method.
  • Định nghĩa interface theo implementation thay vì nhu cầu caller.
  • Tạo interface chỉ vì “best practice” dù chỉ có một usage concrete và không cần seam.
  • Typed nil trong interface.

Điều cần mang sang bài tiếp theo

  • Accept interfaces khi caller cần behavior; return concrete types thường đơn giản.
  • Interface nhỏ dễ implement, test và compose.
  • Implicit implementation là một trong những điểm mạnh nhất của Go.
