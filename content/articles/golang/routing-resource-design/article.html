Routing tốt không nằm ở việc router nào nhanh hơn vài nanosecond. Giá trị lớn hơn là resource boundary rõ, method semantics đúng và API dễ evolve.

1. Resource trước endpoint

Hãy bắt đầu từ noun: users, orders, jobs. Sau đó dùng HTTP method để biểu đạt hành động chuẩn thay vì biến URL thành tên function RPC tùy tiện.

2. Route với ServeMux

gomux := http.NewServeMux()
mux.HandleFunc("GET /users/{id}", getUser)
mux.HandleFunc("POST /orders", createOrder)
mux.HandleFunc("DELETE /orders/{id}", cancelOrder)

3. Method semantics

GET phải safe; PUT thường idempotent; POST không mặc định idempotent. Những semantics này ảnh hưởng cache, retry và client behavior.

4. Versioning và compatibility

Ưu tiên additive change khi có thể. Breaking change nên có migration path rõ ràng thay vì chỉ đổi response shape rồi hy vọng client cập nhật.

Backend realityAPI contract là dependency giữa team/service. Compatibility thường quan trọng hơn route đẹp.

Điểm cần nhớ

  • Route phản ánh resource model.
  • HTTP method semantics ảnh hưởng reliability.
  • Compatibility là một phần của architecture.
