Khi mỗi handler tự quyết định format lỗi, API nhanh chóng trở nên không nhất quán. Hãy có một error model đủ nhỏ và mapping rõ giữa domain failure với HTTP.

1. Một writer helper nhỏ

gofunc writeJSON(w http.ResponseWriter, status int, v any) error {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    return json.NewEncoder(w).Encode(v)
}

2. Domain error không phải HTTP error

Service layer có thể trả ErrNotFound, ErrConflict, ErrForbidden. HTTP layer mới map chúng sang 404/409/403.

3. Status code là signal

400 cho request invalid, 401 cho chưa authenticate, 403 cho không được phép, 404 cho resource không tồn tại, 409 cho conflict. 500 dành cho lỗi server mà client không thể tự sửa request để giải quyết.

4. Log một lần ở boundary

Nếu mọi layer đều log cùng error, bạn có thể tạo bốn dòng log cho một failure. Thường nên wrap context khi propagate và log tại boundary đủ thông tin.

Error hygieneReturn errors upward; log where you have request context and know whether it was already handled.

Điểm cần nhớ

  • Domain layer không nên phụ thuộc HTTP status.
  • Status code và JSON error là API contract.
  • Tránh duplicate logging.
