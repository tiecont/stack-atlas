1. Concurrent code cần error semantics rõ ràng

Khi 10 goroutine chạy cùng lúc và 1 cái lỗi, bạn cần quyết định: dừng tất cả, tiếp tục phần còn lại, hay gom toàn bộ lỗi?

2. errgroup

Gog, ctx := errgroup.WithContext(ctx)

g.Go(func() error { return fetchA(ctx) })
g.Go(func() error { return fetchB(ctx) })

if err := g.Wait(); err != nil {
    return err
}

3. Cancel sibling tasks

Với errgroup.WithContext, khi một task trả lỗi, context được cancel để task khác có cơ hội dừng sớm.

4. Khi cần collect all errors

Không phải lúc nào “first error wins” cũng đúng. Batch validation có thể cần gom lỗi theo item. Khi đó dùng result struct chứa value + error hoặc một aggregator riêng.

5. Error propagation là thiết kế API

Câu hỏi cần trả lờiLỗi nào retryable? task nào độc lập? có partial success không? cancellation có phải lỗi không? Khi semantics rõ, code concurrent sẽ dễ reasoning hơn nhiều.
