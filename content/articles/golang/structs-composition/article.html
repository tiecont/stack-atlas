1. Mental model

Struct là cách Go gom dữ liệu có liên quan thành một type. Go không xây object model quanh class inheritance; thay vào đó code thường dùng composition, nhỏ và tường minh.

Điều quan trọng không phải biến mọi database table thành struct 1:1, mà là tạo type diễn đạt đúng boundary: request DTO, domain model, database row hoặc response có thể là những type khác nhau.

2. Code đầu tiên

Gotype Money struct {
    Amount   int64
    Currency string
}

type Order struct {
    ID    string
    Total Money
}

3. Hiểu sâu hơn

Field viết hoa được export khỏi package; field chữ thường là package-private. Embedding cho phép promote method/field nhưng vẫn là composition, không biến type thành subclass theo nghĩa OOP cổ điển.

Struct value có semantics copy khi assign/pass-by-value. Nếu chứa slice/map/pointer thì copy struct không đồng nghĩa deep copy toàn bộ graph.

4. Khi đặt vào backend thật

Một codebase Go dễ bảo trì thường phân biệt transport model và domain behavior. Ví dụ HTTP request có field optional/string raw; domain model có type đã validate; persistence model có metadata phục vụ database.

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Một `User` struct dùng cho DB, JSON request, JSON response, Kafka event và domain cùng lúc.
  • Embedding chỉ để “giả inheritance”.
  • Giả định copy struct sẽ deep-copy slice/map bên trong.

Điều cần mang sang bài tiếp theo

  • Struct nên diễn đạt một vai trò rõ ràng.
  • Composition thường đơn giản hơn inheritance hierarchy.
  • Boundary type rõ giúp validation và migration an toàn hơn.
