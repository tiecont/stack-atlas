Khi code gọi https://api.example.com, TCP không kết nối với hostname. Trước đó hệ thống phải resolve hostname thành một hoặc nhiều IP address.

1. Lookup trong Go

goips, err := net.LookupIP("example.com")
if err != nil {
    return err
}
for _, ip := range ips {
    fmt.Println(ip)
}

Trong code production, bạn thường để net.Dialer và HTTP transport thực hiện resolution thay vì tự lookup rồi hard-code IP.

2. Một hostname có thể có nhiều IP

Điều này hỗ trợ redundancy, geo routing và load distribution. Vì thế “DNS resolve thành IP nào” là thông tin quan trọng khi một subset request lỗi.

3. Các failure mode

  • NXDOMAIN / hostname sai.
  • Resolver timeout.
  • Record mới nhưng cache chưa hết TTL.
  • IPv4/IPv6 path có hành vi khác nhau.
  • Container/Kubernetes DNS gặp saturation hoặc upstream issue.
DebuggingNếu request lỗi trước khi connect được, log/trace nên giúp phân biệt DNS latency với TCP connect latency. net/http/httptrace có hook cho các phase này.

4. Resolver là dependency

Ở production, DNS không phải phép thuật “luôn hoạt động”. Nó là một hệ thống phân tán khác mà service của bạn phụ thuộc vào. Vì vậy network debugging nên quan sát DNS thay vì chỉ ping IP.
