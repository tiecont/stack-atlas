HTTP là application protocol chạy trên transport. Framework làm HTTP trông như function call, nhưng trên wire vẫn là request, headers, body và response đi qua connection.

1. Request có cấu trúc

httpGET /users/42?expand=orders HTTP/1.1
Host: api.example.com
Accept: application/json
Authorization: Bearer ...

Method và path không phải function name. Headers mang metadata. Body có thể không tồn tại. Response cũng có status line, headers và body.

2. Một TCP connection có thể phục vụ nhiều HTTP request

Việc reuse connection giúp tránh lặp lại TCP/TLS handshake. Đây là lý do connection pooling ở HTTP client quan trọng đến vậy.

3. Body là stream

Trong Go, Request.Body và Response.Body là stream interface. Bạn không bắt buộc load toàn bộ payload vào RAM. Đây là lợi thế lớn khi upload/download dữ liệu lớn.

goresp, err := client.Do(req)
if err != nil { return err }
defer resp.Body.Close()

_, err = io.Copy(dst, resp.Body)
Một thói quen quan trọngHTTP response body cần được đóng. Connection reuse còn phụ thuộc vào việc body được xử lý đúng theo semantics của transport.

4. HTTP error không giống network error

503 Service Unavailable nghĩa là bạn đã nhận được HTTP response. connection refused nghĩa là chưa có HTTP response nào cả. Tách hai loại lỗi này là nền tảng cho retry và observability.
