Distributed system không có timeout thì một dependency chậm có thể giữ goroutine, connection và request vô thời hạn. Nhưng timeout quá ngắn hoặc retry thiếu kiểm soát cũng tạo lỗi giả và retry storm.

1. Có nhiều loại timeout

  • Dial/connect timeout.
  • TLS handshake timeout.
  • Response header timeout.
  • Whole-request timeout.
  • Server read/write/idle timeout.
  • Business deadline từ request context.

2. Request deadline bằng context

goctx, cancel := context.WithTimeout(r.Context(), 800*time.Millisecond)
defer cancel()

req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
if err != nil { return err }
resp, err := client.Do(req)

Nếu client hủy request, context cha có thể cancel các dependency phía dưới thay vì để chúng tiếp tục làm việc vô ích.

3. net.Conn deadline khác context

Deadline trên connection tác động trực tiếp tới I/O của connection. Context là lifecycle abstraction được các API cấp cao tôn trọng. Hai cơ chế liên quan nhưng không đồng nhất.

Anti-patternKhông đặt timeout 30s ở API, rồi dependency A 30s, dependency B 30s. Request cha chỉ có một budget. Child work nên biết thời gian còn lại.

4. Timeout và retry phải thiết kế cùng nhau

Nếu timeout 1 giây rồi retry 3 lần, worst-case có thể vượt latency SLO đáng kể. Retry cũng cần xét idempotency và error class, không phải lỗi nào cũng retry.
