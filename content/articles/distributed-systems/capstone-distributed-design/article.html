Tổng hợp replication, partitioning, idempotency và failure handling. Bài viết ưu tiên mental model, failure mode và cách áp dụng vào production thay vì chỉ nhớ thuật ngữ.

Bài toán

Thiết kế Order Reservation Service: API nhận request tạo reservation, chống duplicate, lưu state, phát event và chịu được instance crash/retry.

Một design khả thi

PostgreSQL giữ source of truth + unique idempotency key; transaction ghi reservation + outbox. Relay publish Kafka; consumers idempotent. API timeout không làm client mất khả năng retry cùng key.

Failure drills

Test: DB commit xong process chết; relay publish xong chưa mark; Kafka unavailable; consumer side effect xong trước commit; replica/read lag.

Review checklist

Cho mỗi arrow trên diagram, ghi: timeout, retry owner, idempotency, consistency, durability, observability và behavior khi dependency unavailable.

Tiêu chuẩn hoàn thànhBạn không chỉ vẽ box; bạn có thể mô tả state transition khi từng box hoặc từng network link gặp lỗi.

Điểm cần nhớ

  • Architecture tốt mô tả failure behavior.
  • Mỗi network edge cần timeout/retry/idempotency contract.
  • Distributed design là quản lý uncertainty có hệ thống.
