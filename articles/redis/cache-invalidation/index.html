Cache Invalidation: bài toán khó thật sự

Delete-on-write, versioned keys, event-driven invalidation và race giữa reader với writer.

“Chỉ xóa cache sau khi update DB” nghe đơn giản, nhưng concurrency có thể tạo stale repopulation. Invalidation tốt cần hiểu timeline.

1. Delete after DB commit

Pattern phổ biến: commit database trước, sau đó delete key. Nếu delete fail, TTL là safety net.

2. Stale repopulation race

3. Versioned keys

Một số hệ thống encode version/generation vào key để tránh overwrite generation mới bằng result cũ.

4. Event invalidation

Trong hệ thống nhiều service, CDC/event có thể invalidate derived caches. Nhưng lúc đó invalidation cũng trở thành distributed messaging problem.

Điểm cần nhớ

  • Invalidation có concurrency races.
  • TTL là safety net, không thay correctness strategy.
  • Event invalidation thêm eventual consistency.
