Atomicity, Transactions và Lua trong Redis

Hiểu command atomicity, race read-modify-write và khi cần MULTI/EXEC hoặc server-side script.

Part of Golang Backend EngineeringRedis & Caching · Lesson 10

Redis xử lý commands theo model khiến từng command riêng lẻ có atomic semantics, nhưng workflow gồm nhiều commands vẫn có race window. “Redis single-threaded” không có nghĩa application transaction tự nhiên atomic.

1. Atomic command

INCR an toàn hơn GET → parse → SET cho counter concurrent vì mutation xảy ra trong một command.

2. Multi-command race

textv := GET key
if v < limit {
    SET key v+1
}

Hai clients có thể cùng đọc cùng value trước khi ghi.

3. MULTI/EXEC và WATCH

Redis transaction groups commands; optimistic concurrency có thể dùng WATCH tùy workflow.

4. Lua/server-side logic

Script giúp đưa check-and-update thành một server-side atomic operation. Nhưng script dài/đắt có thể block Redis event processing.

Điểm cần nhớ

  • Single command atomic không làm multi-command workflow atomic.
  • Prefer built-in atomic commands khi có.
  • Lua mạnh nhưng phải ngắn và bounded.
Bài tập thực hànhThiết kế fixed-window rate limiter bằng INCR + EXPIRE sao cho tránh race setup TTL.
