Cache là gì và tại sao nó khó?

Hiểu cache như một bản sao dữ liệu: nhanh hơn nhưng thêm consistency, expiry và failure mode.

Cache thường được giới thiệu bằng một câu rất hấp dẫn: “đừng query database nữa”. Nhưng production cache không chỉ là tốc độ. Bạn đang tạo thêm một bản sao của dữ liệu, và từ khoảnh khắc đó hệ thống có thêm bài toán freshness, invalidation và failure.

1. Cache nằm ở đâu?

Cache có thể nằm trong process, trong Redis, ở CDN hoặc ngay trong database buffer. Trong backend Go, hai tầng thường gặp nhất là local cache và distributed cache.

2. Hit và miss

Cache hit: key đã có và còn hợp lệ. Cache miss: phải đọc origin, rồi có thể populate cache cho lần sau.

govalue, err := cache.Get(ctx, key)
if err == nil {
    return value, nil
}

value, err = repo.Load(ctx, id)
if err != nil { return Result{}, err }
_ = cache.Set(ctx, key, value, 5*time.Minute)
return value, nil

3. Cache không phải source of truth

Với cache-aside thông thường, PostgreSQL vẫn là source of truth. Cache có thể mất toàn bộ dữ liệu mà correctness lâu dài vẫn phục hồi được.

4. Cost của một bản copy

Mental modelCache đổi latency lấy thêm state. Mỗi bản copy mới đều cần trả lời: khi nào tạo, khi nào hết hạn, khi nào xóa, và nếu stale thì có chấp nhận được không?

Điểm cần nhớ

  • Cache là bản sao, không phải phép thuật.
  • Hit ratio chỉ có ý nghĩa cùng với correctness.
  • Luôn xác định source of truth.
