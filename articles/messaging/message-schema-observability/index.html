Schema Evolution, Tracing và Observability

Theo dõi message từ producer tới consumer, đo lag/retry và evolve schema mà không phá deploy độc lập.

Part of Golang Backend EngineeringMessaging · Lesson 11

Async system khó debug hơn sync call vì producer và consumer không cùng request stack. Vì vậy message metadata và observability phải được thiết kế từ đầu.

1. Trace context

Propagate trace/correlation metadata qua message headers/envelope để nối producer span và consumer processing.

2. Metrics

Publish rate, consume rate, processing latency, error rate, retry count, DLQ size và lag/backlog là baseline.

3. Structured logs

Log event ID, type, key, consumer name và attempt. Tránh log full payload nếu có PII/secrets.

4. Schema compatibility

Consumer tolerant reader + additive fields giúp rolling deployments. Với ecosystem lớn, schema registry/Protobuf/Avro có thể formalize compatibility.

Điểm cần nhớ

  • Async trace cần metadata propagation.
  • Lag + retry + DLQ là core signals.
  • Schema evolution là deployment problem.
