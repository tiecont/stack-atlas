CAP Theorem: dùng đúng, đừng dùng như slogan

Part of Golang Backend EngineeringDistributed Systems · Lesson 05

CAP nói về lựa chọn khi network partition xảy ra. Bài viết ưu tiên mental model, failure mode và cách áp dụng vào production thay vì chỉ nhớ thuật ngữ.

Ba chữ

C = consistency theo mô hình CAP; A = mọi request tới non-failing node nhận response; P = hệ thống tiếp tục trong network partition. Trong hệ thống phân tán thật, partition là điều phải xử lý.

CP intuition

Khi không thể xác minh quorum/leader, hệ thống từ chối một số operation để tránh divergent truth.

AP intuition

Các phía vẫn nhận write/read nhưng có thể tạm diverge và cần conflict resolution.

CAP không chọn database thay bạn

Database có thể có nhiều operation/config cho guarantee khác nhau. Hỏi cụ thể read/write path và failure mode, đừng dán nhãn “DB này là AP” rồi dừng reasoning.

Điểm cần nhớ

  • CAP tập trung vào network partition.
  • C/A trade-off xảy ra khi partition.
  • Hệ thống thực tế có nhiều mức consistency/config.
