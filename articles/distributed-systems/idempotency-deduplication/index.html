Idempotency và Deduplication

Retry là inevitability; side effect phải chịu được retry.

Retry là inevitability; side effect phải chịu được retry. Bài viết ưu tiên mental model, failure mode và cách áp dụng vào production thay vì chỉ nhớ thuật ngữ.

Idempotent operation

Gọi operation nhiều lần cho cùng logical request cho kết quả tương đương một lần. PUT state thường dễ idempotent hơn “increment”.

Idempotency key

Client gửi stable request ID; server lưu kết quả/claim của ID đó để retry không tạo payment/order thứ hai.

sqlINSERT INTO idempotency_keys(key, status)
VALUES ($1, 'processing')
ON CONFLICT (key) DO NOTHING;

Dedup window

Lưu key mãi có cost; TTL/dedup window phải lớn hơn retry/replay horizon nếu muốn guarantee có ý nghĩa.

Exactly-once illusion

Thay vì cố “delivery đúng một lần”, thường dễ hơn khi chấp nhận at-least-once delivery và làm effect idempotent.

Điểm cần nhớ

  • Retry-safe effect quan trọng hơn delivery slogan.
  • Idempotency key cần scope và retention.
  • Unique constraint là công cụ correctness mạnh.
