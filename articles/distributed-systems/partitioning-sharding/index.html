Partitioning, Sharding và Consistent Hashing

Scale data bằng cách chia ownership.

Part of Golang Backend EngineeringDistributed Systems · Lesson 09

Scale data bằng cách chia ownership. Bài viết ưu tiên mental model, failure mode và cách áp dụng vào production thay vì chỉ nhớ thuật ngữ.

Range vs hash

Range partitioning tốt cho range scan nhưng dễ hotspot nếu key tăng tuần tự. Hash partitioning phân phối đều hơn nhưng range query khó hơn.

Shard key

Shard key quyết định locality, fan-out query và hotspot. Đây thường là quyết định data model dài hạn.

Consistent hashing

Consistent hashing giảm lượng key phải di chuyển khi node membership thay đổi so với modulo đơn giản. Virtual nodes giúp cân bằng tốt hơn.

Rebalancing

Thêm shard không miễn phí: phải copy data, giữ consistency, throttle bandwidth và tránh overload source/target.

Điểm cần nhớ

  • Shard key quyết định query shape.
  • Consistent hashing giảm remap khi membership đổi.
  • Rebalance là production workload thật.
