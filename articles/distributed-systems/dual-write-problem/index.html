Dual Write Problem

Ghi DB rồi publish message là hai side effect độc lập và có thể lệch nhau.

Distributed Systems
On this pageDB trước, message sauMessage trước, DB sauKết luận
Part of Golang Backend EngineeringDistributed Transactions · Lesson 02

DB trước, message sau

tx.Commit()        // success
producer.Publish() // crash here

DB có dữ liệu nhưng event biến mất.

Message trước, DB sau

producer.Publish() // success
tx.Commit()        // fails

Consumer thấy event cho state chưa tồn tại.

Kết luận

Hai write độc lập không tự nhiên trở thành atomic chỉ vì chúng nằm cạnh nhau trong code.
