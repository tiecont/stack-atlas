Constraints và Data Invariants

Đưa invariant cuối cùng xuống database thay vì chỉ kiểm tra bằng if trước khi write.

Part of Golang Backend EngineeringPostgreSQL with Go · Lesson 13

Application check có thể race. Database constraint được evaluate tại nơi serialize writes và thường là lớp bảo vệ chắc chắn hơn cho invariant đơn giản.

1. Unique

sqlALTER TABLE users
ADD CONSTRAINT users_email_unique UNIQUE (email);

2. Check constraint

sqlALTER TABLE accounts
ADD CONSTRAINT balance_non_negative CHECK (balance >= 0);

3. Foreign key

FK bảo vệ referential integrity, nhưng cascade behavior cần thiết kế rõ.

4. App validation vẫn cần

Constraint không thay UX validation. App validate để feedback tốt; DB constraint để bảo vệ correctness dưới concurrency.

Defense in depthValidate ở app, enforce invariant ở DB khi có thể.

Điểm cần nhớ

  • Application pre-check có thể race.
  • Constraint là correctness primitive.
  • Translate constraint errors thành domain errors.
Bài tập thực hànhLiệt kê invariant của users/jobs/applications và quyết định invariant nào nên có DB constraint.
