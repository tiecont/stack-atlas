Schema và Migrations

Thiết kế schema như contract lâu dài, migrate an toàn khi nhiều app version cùng chạy.

Schema production sống lâu hơn một deploy. Migration tốt phải xét lock, table rewrite, backward compatibility và rollout order.

1. Constraint ở database

NOT NULL, UNIQUE, foreign key và CHECK constraint là lớp bảo vệ cuối cùng cho invariant dữ liệu.

2. Expand → migrate → contract

Với breaking change, thường thêm schema mới tương thích trước, deploy code đọc/ghi mới, backfill rồi mới remove cũ.

3. Migration có thể lock

Một ALTER TABLE tưởng nhỏ có thể chặn traffic tùy operation/version/data size. Luôn hiểu lock behavior.

4. App startup không phải lúc nào cũng nên auto-migrate

Nhiều team chạy migrations như deployment step riêng để kiểm soát quyền, timeout và rollback.

Production ruleMigration là production operation, không chỉ file SQL trong repo.

Điểm cần nhớ

  • Schema constraints bảo vệ invariant.
  • Migrate theo compatibility window.
  • Hiểu lock trước khi chạy DDL lớn.
