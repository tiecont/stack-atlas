Row Locks và Concurrency Control

SELECT FOR UPDATE, pessimistic vs optimistic locking và cách tránh giữ lock quá lâu.

Postgresql

Part of Golang Backend EngineeringPostgreSQL with Go · Lesson 08

Khi nhiều request cùng sửa một entity, bạn cần chiến lược concurrency control. Lock là công cụ, không phải mặc định cho mọi vấn đề.

1. Pessimistic locking

sqlSELECT id, stock
FROM products
WHERE id = $1
FOR UPDATE

2. Optimistic locking

sqlUPDATE documents
SET body = $1, version = version + 1
WHERE id = $2 AND version = $3

3. Lock order

Nếu transaction A lock account 1 rồi 2, còn B lock 2 rồi 1, deadlock có thể xảy ra. Consistent lock order giảm risk.

4. Lock wait là latency

Query chậm không nhất thiết đang tính toán; nó có thể đang chờ lock.

DebugPhân biệt execution time với lock wait trước khi thêm index.

Điểm cần nhớ

  • Pessimistic lock phù hợp contention/invariant nhất định.
  • Optimistic locking dùng version/conflict detection.
  • Lock order ảnh hưởng deadlock.
