Retry Deadlock và Serialization Failures

Retry đúng lỗi, có backoff và chỉ khi transaction operation đủ an toàn để chạy lại.

PostgreSQL có thể abort transaction vì deadlock hoặc serializable conflict. App production cần phân biệt retryable errors với permanent errors.

1. Deadlock detection

Database chọn một transaction làm victim để break deadlock. App nhận error và transaction đó bị rollback.

2. Serializable failure

Serializable isolation có thể trả serialization failure dù logic từng statement đúng.

3. Retry whole transaction

Retry thường phải chạy lại toàn bộ transaction function trên transaction mới, không retry một statement giữa transaction đã aborted.

4. Backoff + bound

Retry count phải giới hạn và có jitter/backoff nếu contention có thể tiếp tục.

Side effectsĐừng gửi email/HTTP side effect bên trong transaction function sẽ được retry, nếu side effect không idempotent.

Điểm cần nhớ

  • Retry only classified transient failures.
  • Retry whole transaction.
  • External side effects cần tách/idempotent.
