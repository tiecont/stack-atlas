Isolation Levels và Anomalies

Read Committed, Repeatable Read, Serializable và vì sao transaction không tự động loại bỏ mọi race.

“Có transaction” chưa đủ để nói code concurrent đúng. Isolation level quyết định những hiện tượng nào có thể quan sát giữa transactions.

1. Read Committed

Default PostgreSQL phổ biến: mỗi statement thấy snapshot phù hợp tại thời điểm statement bắt đầu. Hai SELECT trong cùng transaction có thể thấy dữ liệu khác nhau.

2. Repeatable Read

Transaction làm việc trên snapshot ổn định hơn, nhưng concurrent write conflict vẫn cần hiểu.

3. Serializable

PostgreSQL có thể abort transaction nếu execution không thể tương đương serial order. App phải sẵn sàng retry serialization failure.

4. Chọn theo invariant

Điểm cần nhớ

  • Transaction ≠ serial execution.
  • Isolation level thay đổi anomalies.
  • Serializable cần retry strategy.
