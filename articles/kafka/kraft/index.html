KRaft: metadata quorum và controller

Kafka hiện đại không cần ZooKeeper.

Kafka hiện đại không cần ZooKeeper. Bài viết ưu tiên mental model, failure mode và cách áp dụng vào production thay vì chỉ nhớ thuật ngữ.

Metadata plane

KRaft dùng Raft-based metadata quorum để quản lý cluster metadata và controller leadership. Data partitions vẫn là data plane riêng.

Controller role

Controller xử lý metadata changes như broker registration, partition leadership và topic configuration. Controller failure khác với data partition leader failure.

Dedicated vs combined

Cluster nhỏ/lab có thể combined roles; production lớn thường tách controller/broker roles để failure isolation rõ hơn.

Ops implication

KRaft giảm một external dependency nhưng không làm Kafka “stateless”. Metadata quorum vẫn cần sizing, quorum, disk và network reliability.

Điểm cần nhớ

  • KRaft là metadata consensus layer.
  • Controller và broker có responsibility khác nhau.
  • Bỏ ZooKeeper không bỏ operational complexity.
