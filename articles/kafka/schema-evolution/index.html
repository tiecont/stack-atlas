Event contract cần thay đổi mà không phá consumer cũ. Bài viết ưu tiên mental model, failure mode và cách áp dụng vào production thay vì chỉ nhớ thuật ngữ.

Tại sao schema khó

Producer deploy hôm nay có thể tạo event được consumer deploy tháng sau đọc lại. Schema vì vậy là API contract theo thời gian.

Compatibility

Backward/forward compatibility tùy chiến lược rollout. Thêm optional field thường an toàn hơn rename/remove trực tiếp.

Formats

JSON dễ debug nhưng contract lỏng; Protobuf/Avro có schema rõ hơn và tooling compatibility tốt hơn. Chọn theo ecosystem và governance.

Envelope

Event thường nên có event_id, event_type, occurred_at, aggregate key và schema/version metadata. Đừng nhét mọi thứ vào một “generic event” vô nghĩa.

json{
  "event_id": "...",
  "event_type": "order.created",
  "order_id": "o-42",
  "occurred_at": "...",
  "data": {"total": 120000}
}

Điểm cần nhớ

  • Event schema là public contract giữa teams/time.
  • Evolution nên additive khi có thể.
  • Metadata phục vụ dedup, tracing và migration.
