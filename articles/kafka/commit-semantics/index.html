Commit semantics và idempotent consumer

At-least-once là lựa chọn rất phổ biến vì dễ phục hồi.

At-least-once là lựa chọn rất phổ biến vì dễ phục hồi. Bài viết ưu tiên mental model, failure mode và cách áp dụng vào production thay vì chỉ nhớ thuật ngữ.

Process rồi commit

Pattern phổ biến: đọc record → thực hiện side effect → commit offset. Nếu crash sau side effect nhưng trước commit, record sẽ chạy lại.

Idempotent consumer

Dùng business key hoặc event ID để side effect lặp lại vẫn cho cùng kết quả. Ví dụ insert với unique constraint, UPSERT hoặc bảng processed_events.

Inbox pattern

Khi cần transaction với database, có thể ghi event ID và domain update trong cùng DB transaction. Duplicate lần sau bị unique constraint loại bỏ.

Commit batch

Commit theo batch giảm overhead nhưng mở rộng replay window. Chọn dựa trên cost duplicate và throughput.

Điểm cần nhớ

  • At-least-once đòi hỏi idempotent side effects.
  • Commit offset không phải business transaction.
  • Replay window là tham số thiết kế.
