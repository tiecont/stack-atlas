io.Reader, io.Writer và Standard Library

Hai interface nhỏ mở ra file, HTTP body, compression, hashing và streaming mà không cần load tất cả vào RAM.

1. Mental model

`io.Reader` và `io.Writer` là hai abstraction trung tâm của Go ecosystem. Nếu một component có thể đọc bytes tuần tự, nó có thể trở thành nguồn cho rất nhiều API mà không cần biết dữ liệu đến từ file, network hay memory.

Đây là ví dụ điển hình cho triết lý interface nhỏ + composition.

2. Code đầu tiên

Gofunc hash(r io.Reader) (string, error) {
    h := sha256.New()
    if _, err := io.Copy(h, r); err != nil {
        return "", err
    }
    return hex.EncodeToString(h.Sum(nil)), nil
}

3. Hiểu sâu hơn

Streaming giúp tránh `ReadAll` cho payload lớn. `io.Copy` nối Reader và Writer hiệu quả. Nhiều package như `gzip`, `bufio`, `http`, `os`, `crypto` có thể compose quanh hai interface này.

Đọc standard library là cách học Go rất tốt: naming, error semantics và interface design đều phản ánh idiom của ecosystem.

Examplesrc, _ := os.Open("large.bin")
defer src.Close()
dst, _ := os.Create("copy.bin")
defer dst.Close()
_, err := io.Copy(dst, src)

4. Khi đặt vào backend thật

Upload file, proxy response, compress stream, hash object, parse request body — tất cả đều hưởng lợi từ streaming. Một backend engineer nên mặc định hỏi “có cần materialize toàn bộ dữ liệu vào memory không?”

Câu hỏi nên tự hỏiKhi concept này đi qua HTTP, database, cache hoặc worker, ownership nằm ở đâu, lifecycle kết thúc khi nào, và failure được biểu diễn ra sao?

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • `io.ReadAll` với body không giới hạn.
  • Quên đóng resource khi bạn sở hữu lifecycle của nó.
  • Bọc quá nhiều buffer mà không đo performance.

Điều cần mang sang bài tiếp theo

  • Reader/Writer là protocol nhỏ cho streaming.
  • Composition của standard library thường tốt hơn tự tạo framework.
  • Đối với dữ liệu lớn, stream trước, buffer khi có lý do.
