Idempotency và Safe Writes

Làm POST có thể retry an toàn khi network timeout khiến client không biết server đã commit hay chưa.

Golang

Part of Golang Backend EngineeringProduction HTTP Server · Lesson 09

Trong distributed systems, timeout không nói rằng operation thất bại. Server có thể đã commit nhưng response bị mất. Idempotency là cách biến retry thành hành vi có kiểm soát.

1. Ambiguous timeout

Client retry một payment/order create có thể tạo duplicate nếu server không có idempotency strategy.

2. Idempotency key

httpPOST /payments
Idempotency-Key: 9b703f0c-...

{ "order_id": "ord_123", "amount": 50000 }

3. Store result atomically

Key phải được ràng buộc với request identity/payload và result trong transaction phù hợp. Chỉ cache response trong memory không đủ khi nhiều instance xử lý.

4. Unique constraint là đồng minh

Business identifier có unique constraint ở DB giúp biến race thành conflict có thể xử lý thay vì duplicate im lặng.

Điểm cần nhớ

  • Timeout có thể xảy ra sau commit.
  • Idempotency key cần storage semantics.
  • Unique constraint bảo vệ invariant cuối cùng.
