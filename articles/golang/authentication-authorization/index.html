Authentication và Authorization

Tách “bạn là ai” khỏi “bạn được phép làm gì”, và đưa principal qua request lifecycle an toàn.

Golang

Part of Golang Backend EngineeringProduction HTTP Server · Lesson 07

Auth thường bị gom thành một middleware khổng lồ. Thiết kế sạch tách credential verification, principal extraction và authorization policy.

1. Authentication

Authentication xác minh identity từ session, token hoặc mTLS. Kết quả nên là principal đã được validate, không phải raw token.

2. Authorization

Authorization trả lời principal này có được đọc/sửa resource cụ thể hay không. Nhiều rule cần dữ liệu domain nên không nhất thiết nằm toàn bộ trong middleware.

3. Đưa principal qua context

gotype principalKey struct{}

func WithPrincipal(ctx context.Context, p Principal) context.Context {
    return context.WithValue(ctx, principalKey{}, p)
}

4. Fail closed

Nếu auth dependency lỗi hoặc policy không resolve được, mặc định không nên cấp quyền. Authorization bug là security bug.

Quan trọng401 và 403 khác nhau: chưa xác thực khác với đã xác thực nhưng không đủ quyền.

Điểm cần nhớ

  • Authentication ≠ authorization.
  • Principal nên là dữ liệu đã verify.
  • Authorization gắn với resource/business rule.
