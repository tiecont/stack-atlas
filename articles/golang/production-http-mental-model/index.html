Production HTTP Server: nhìn toàn bộ request lifecycle

Từ socket đến handler, dependency và response: hiểu request path trước khi thêm framework.

Một API production không chỉ là route trả JSON. Mỗi request tiêu thụ connection, goroutine, CPU, memory và downstream capacity. Thiết kế tốt bắt đầu bằng việc nhìn toàn bộ lifecycle.

1. Request đi qua những tầng nào?

Một request thường đi qua load balancer hoặc ingress, HTTP server, middleware, handler, service và persistence layer. Mỗi tầng có thể thêm latency hoặc failure mode.

2. Critical path và optional work

Công việc bắt buộc để trả response nên ở critical path. Email, analytics hoặc indexing thường có thể chuyển sang async nếu business invariant cho phép.

Quy tắcĐừng làm thêm synchronous work chỉ vì code dễ viết. Mỗi dependency trên critical path làm tăng latency và failure surface.

3. Stateless để scale ngang

Handler không nên phụ thuộc vào session nằm trong memory của một instance nếu request tiếp theo có thể đến pod khác.

gofunc HandleOrder(w http.ResponseWriter, r *http.Request) {
    ctx := r.Context()
    // state nằm ở DB/cache hoặc được truyền qua request
    _ = ctx
}

4. Thiết kế bằng SLO và budget

Trước khi chọn timeout, concurrency hay cache, hãy biết latency SLO và error budget. Production engineering là quản lý budget chứ không phải thêm middleware vô hạn.

Điểm cần nhớ

  • Request lifecycle là resource lifecycle.
  • Critical path càng dài càng dễ lỗi.
  • Stateless giúp horizontal scaling nhưng state vẫn phải sống ở đâu đó.
