Stack vs Heap

Object lifetime quan trọng hơn “local = stack”; compiler quyết định placement bằng escape analysis.

1. Mental model

Cách nói “biến local nằm trên stack, `new` nằm trên heap” không đúng với Go. Compiler quyết định storage dựa trên lifetime và escape analysis. Một value local có thể lên heap; một allocation expression không nhất thiết tạo heap allocation theo cách bạn tưởng sau optimization.

Stack allocation thường rẻ và lifetime gắn với goroutine frame; heap object cần được GC quản lý.

Runtime noteNội dung runtime được viết theo Go 1.27 hiện hành. Các chi tiết implementation có thể thay đổi; language/spec behavior mới là contract ổn định.

2. Code đầu tiên

Gofunc makeUser() *User {
    u := User{Name: "Lan"}
    return &u // u must outlive this function call
}

3. Hiểu sâu hơn

Trong ví dụ, pointer được trả ra nên storage của `u` phải sống sau khi function kết thúc; compiler có thể quyết định nó escape. Nhưng hãy dùng compiler diagnostics thay vì đoán.

Goroutine stacks có thể thay đổi kích thước khi cần; bạn không nên viết code dựa vào địa chỉ stack ổn định như trong low-level manual memory model.

Examplego test -gcflags="-m=2" ./...
# inspect escape decisions, do not guess

4. Khi đặt vào backend thật

Heap allocation nhiều làm tăng allocation rate và GC work. Nhưng optimization chỉ có ý nghĩa sau profiling. Với API I/O-bound, giảm một allocation nhỏ có thể không đáng bằng giảm query hoặc network round trip.

Câu hỏi nên tự hỏiKhi concept này đi qua HTTP, database, cache hoặc worker, ownership nằm ở đâu, lifecycle kết thúc khi nào, và failure được biểu diễn ra sao?

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Ám ảnh “mọi pointer đều heap”.
  • Thay pointer bằng value khắp nơi chỉ để tránh GC mà phá semantics/copy cost.
  • Tối ưu allocation khi profile cho thấy bottleneck ở DB.

Điều cần mang sang bài tiếp theo

  • Placement là quyết định của compiler dựa trên lifetime.
  • Stack/heap là performance model, không nên leak vào business design quá sớm.
  • Đo allocation trước khi tối ưu.
