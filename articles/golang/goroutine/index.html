Part of Golang Backend EngineeringGo Concurrency · Lesson 01

Khi mới học Go, sớm hay muộn bạn cũng gặp từ goroutine. Nghe có vẻ là một khái niệm “hệ thống” khó nhằn, nhưng trực giác ban đầu thực ra rất đơn giản: một công việc không nhất thiết phải đứng chờ một công việc độc lập khác hoàn thành.

1. Bắt đầu từ một vấn đề rất đời thường

Giả sử bạn đang chuẩn bị bữa sáng. Có hai việc: pha cà phê và nướng bánh. Nếu làm theo kiểu tuần tự, bạn sẽ đứng chờ máy pha cà phê xong rồi mới bật máy nướng bánh.

Gopackage main

import (
    "fmt"
    "time"
)

func makeCoffee() {
    time.Sleep(2 * time.Second)
    fmt.Println("Coffee is ready")
}

func makeToast() {
    time.Sleep(2 * time.Second)
    fmt.Println("Toast is ready")
}

func main() {
    makeCoffee()
    makeToast()
}
Ý tưởng quan trọngConcurrency không có nghĩa mọi thứ luôn chạy song song trên CPU. Nó có nghĩa nhiều công việc có thể cùng tồn tại, được phối hợp và tiến triển trong cùng một khoảng thời gian.

2. Goroutine là gì?

Cách hiểu đơn giản nhất:

GoroutineLà một công việc có thể chạy độc lập với các công việc khác trong cùng chương trình Go. Go runtime chịu trách nhiệm quản lý và schedule các goroutine.

Một backend Go có thể đồng thời có rất nhiều loại công việc:

Mental modelgoroutine A → xử lý HTTP request
goroutine B → đọc Kafka message
goroutine C → gọi Redis
goroutine D → chạy background job
goroutine E → ghi log

Goroutine không phải một OS thread riêng

Goroutine được Go runtime quản lý và thường nhẹ hơn việc tạo một OS thread cho từng công việc. Runtime sẽ phân phối nhiều goroutine lên một số OS thread để thực thi.

3. Chỉ một từ khóa: go

Lời gọi bình thường:

GomakeCoffee()

có nghĩa gần như: chạy function này và chờ nó hoàn thành rồi mới đi tiếp.

Còn:

Gogo makeCoffee()

có nghĩa gần như: bắt đầu công việc này trong một goroutine, còn goroutine hiện tại có thể tiếp tục.

Function bình thường

A chạy xong → sau đó B mới chạy.

Goroutine

A có thể bắt đầu, rồi B vẫn có thể tiến triển mà không cần đợi A hoàn thành.

4. Khi main() kết thúc, chương trình cũng kết thúc

Đây là lỗi rất thường gặp khi mới học goroutine:

Gopackage main

import "fmt"

func sayHello() {
    fmt.Println("Hello from goroutine")
}

func main() {
    go sayHello()
}

Không có gì đảm bảo sayHello() kịp chạy trước khi main() kết thúc.

Đừng dùng Sleep để “đợi cho chắc”time.Sleep() chỉ phù hợp cho demo. Trong code thật, hãy đồng bộ bằng cơ chế đúng như WaitGroup, channel hoặc higher-level primitives.

5. Chờ goroutine bằng sync.WaitGroup

Nếu mục tiêu của bạn chỉ là: “Tôi có N công việc và muốn đợi tất cả hoàn thành”, WaitGroup là công cụ rất tự nhiên.

Gopackage main

import (
    "fmt"
    "sync"
    "time"
)

func main() {
    var wg sync.WaitGroup

    wg.Add(1)

    go func() {
        defer wg.Done()

        time.Sleep(2 * time.Second)
        fmt.Println("Task completed")
    }()

    wg.Wait()
    fmt.Println("Program finished")
}

6. Goroutine đặc biệt hữu ích với I/O

Backend dành rất nhiều thời gian để chờ: database, Redis, HTTP API, Kafka, filesystem, network. Trong lúc một request đang chờ I/O, chương trình có thể xử lý các request khác.

Ví dụ ba API độc lập

Nếu ba call không phụ thuộc nhau, chạy tuần tự có thể mất gần tổng thời gian của cả ba.

Pseudo Gouser := getUser()        // ~500ms
orders := getOrders()    // ~500ms
payment := getPayment()  // ~500ms

// tổng gần ~1500ms

Nếu thiết kế chúng chạy concurrent và đồng bộ kết quả đúng cách, tổng latency có thể gần với call chậm nhất thay vì tổng của tất cả.

7. Concurrency tạo ra vấn đề mới: Race Condition

Goroutine giúp nhiều việc cùng tiến triển, nhưng nếu nhiều goroutine cùng đọc và ghi một vùng dữ liệu chung, bạn phải nghĩ đến synchronization.

Gocounter := 0

go func() {
    counter++
}()

go func() {
    counter++
}()
Goroutine không làm code tự động “an toàn”Concurrency là sức mạnh, nhưng cũng buộc bạn quản lý shared state và synchronization rõ ràng hơn.

8. Goroutine leak: công việc không bao giờ kết thúc

Hãy nhìn đoạn code này:

Gofunc worker(ch chan int) {
    value := <-ch
    fmt.Println(value)
}

Nếu không ai gửi dữ liệu vào ch, goroutine có thể chờ mãi. Nếu server liên tục tạo thêm những goroutine kiểu này, số lượng goroutine sẽ ngày càng tăng.

9. Đừng tạo goroutine vô hạn

Một pattern hấp dẫn nhưng nguy hiểm:

Gofor _, item := range items {
    go process(item)
}

Nếu có một triệu item, bạn có thể tạo một triệu goroutine. Nếu mỗi goroutine lại gọi database, bạn vừa biến concurrency trong app thành một cơn bão request xuống dependency.

Concurrency không làm dependency mạnh hơnNếu database chỉ chịu được 100 connection, việc tạo 100.000 goroutine không khiến database có thêm capacity.
