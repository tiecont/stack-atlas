1. Mental model

“Idiomatic Go” không có nghĩa viết code theo một bộ luật bí mật. Nó thường là những lựa chọn làm code dễ đọc với ecosystem: tên ngắn ở scope ngắn, error tường minh, interface nhỏ, zero value hữu ích, composition và standard library trước abstraction lớn.

Bài cuối Season 01 nên biến kiến thức rời rạc thành một project chạy được.

2. Code đầu tiên

Gotype Store interface {
    Add(ctx context.Context, t Task) error
    List(ctx context.Context) ([]Task, error)
}

type App struct { store Store }

func (a *App) Add(ctx context.Context, title string) error {
    title = strings.TrimSpace(title)
    if title == "" { return ErrEmptyTitle }
    return a.store.Add(ctx, Task{Title: title})
}

3. Hiểu sâu hơn

Mini project gợi ý: CLI Task Manager lưu JSON/file hoặc một HTTP notes service rất nhỏ. Mục tiêu không phải feature nhiều, mà là dùng package, struct, interface có lý do, errors, I/O và tests.

Sau khi chạy được, dùng `go vet`, `go test`, `go fmt` và đọc lại package boundaries. Bạn đã sẵn sàng sang Season 02 khi bắt đầu hỏi: value của mình nằm ở đâu trong memory, append vì sao allocate, GC làm gì?

4. Khi đặt vào backend thật

Thói quen production bắt đầu từ project nhỏ: context ở boundary, errors có context, resource lifecycle rõ, config explicit và tests chạy bằng một command. Framework không thể thay thế những nền tảng này.

Câu hỏi nên tự hỏiKhi concept này đi qua HTTP, database, cache hoặc worker, ownership nằm ở đâu, lifecycle kết thúc khi nào, và failure được biểu diễn ra sao?

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Copy “clean architecture template” 40 folder cho app 300 dòng.
  • Interface ở mọi layer mà không có behavior abstraction thực.
  • Tối ưu structure trước khi domain có shape rõ.

Điều cần mang sang bài tiếp theo

  • Readability là feature.
  • Abstraction nên xuất hiện sau khi pattern/pressure xuất hiện.
  • Season 01 kết thúc khi bạn viết Go rõ ràng; Season 02 bắt đầu khi bạn muốn hiểu nó chạy thế nào.
