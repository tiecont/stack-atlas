1. Mental model

Generics cho phép viết code hoạt động trên nhiều type trong khi vẫn giữ compile-time type safety. Go dùng type parameters và constraints; mục tiêu là abstraction có kiểm soát, không khuyến khích tạo hierarchy phức tạp.

Từ Go 1.27, ngôn ngữ hỗ trợ generic methods trong các trường hợp được định nghĩa bởi spec/release hiện hành, nhưng interface methods vẫn có các giới hạn riêng. Với người mới, generic function/type vẫn là nơi tốt nhất để bắt đầu.

2. Code đầu tiên

Gofunc Contains[T comparable](items []T, target T) bool {
    for _, item := range items {
        if item == target {
            return true
        }
    }
    return false
}

3. Hiểu sâu hơn

Constraint mô tả tập type/operations hợp lệ. `any` là constraint rộng; `comparable` dùng cho type hỗ trợ `==`/`!=` phù hợp để làm map key.

Đừng dùng generic khi interface hoặc function concrete rõ hơn. Generics hợp lý cho container/algorithm mà logic thực sự không phụ thuộc concrete domain type.

Exampletype Page[T any] struct {
    Items []T `json:"items"`
    Next  string `json:"next"`
}

4. Khi đặt vào backend thật

Trong backend, generics thường hữu ích ở infrastructure helpers: typed pagination result, cache wrapper, collection transform. Nhưng một `Repository[T]` quá generic dễ xóa mất semantics khác nhau giữa User, Order, Payment.

Câu hỏi nên tự hỏiKhi concept này đi qua HTTP, database, cache hoặc worker, ownership nằm ở đâu, lifecycle kết thúc khi nào, và failure được biểu diễn ra sao?

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Generic hóa domain repository chỉ để giảm vài dòng code.
  • Constraint quá rộng khiến implementation phải dùng reflection/type switch.
  • Tạo abstraction trước khi có hai use case thực sự.

Điều cần mang sang bài tiếp theo

  • Generics là công cụ giảm duplication của algorithm/type-safe container.
  • Domain semantics quan trọng hơn “DRY tuyệt đối”.
  • Bắt đầu concrete, generalize khi pattern đã rõ.
