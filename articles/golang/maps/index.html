Maps và Set-like Data

Lookup O(1) kỳ vọng chỉ là phần đầu; còn nil map, iteration, key design và concurrency.

1. Mental model

Map là cấu trúc key-value built-in của Go. Cú pháp đơn giản dễ khiến người mới bỏ qua semantics quan trọng: lookup một key không tồn tại vẫn trả zero value, iteration order không nên được dựa vào, và map thông thường không an toàn cho concurrent read/write không được đồng bộ.

Pattern `value, ok := m[key]` là cách phân biệt “không tồn tại” với “tồn tại nhưng value bằng zero”.

2. Code đầu tiên

Gocounts := map[string]int{"go": 3}

n, ok := counts["rust"]
if !ok {
    fmt.Println("missing")
}

counts["rust"] = n + 1

3. Hiểu sâu hơn

Nil map có thể đọc nhưng ghi vào sẽ panic. `make(map[K]V)` tạo map sẵn sàng để write. Key phải comparable; slice chẳng hạn không thể trực tiếp làm key.

Đừng dùng iteration order để tạo output deterministic. Nếu cần stable output, thu keys vào slice rồi sort.

Examplekeys := make([]string, 0, len(m))
for k := range m { keys = append(keys, k) }
sort.Strings(keys)

4. Khi đặt vào backend thật

Map xuất hiện trong caches nhỏ, routing tables, aggregation và deduplication. Khi map trở thành shared mutable state của nhiều goroutine, bạn đã bước vào Season 03: mutex, ownership hoặc cấu trúc concurrent thích hợp.

Câu hỏi nên tự hỏiKhi concept này đi qua HTTP, database, cache hoặc worker, ownership nằm ở đâu, lifecycle kết thúc khi nào, và failure được biểu diễn ra sao?

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Ghi vào nil map.
  • Không dùng `ok` khi zero value là dữ liệu hợp lệ.
  • Phụ thuộc vào thứ tự iteration.
  • Chia sẻ map giữa goroutine mà không synchronization.

Điều cần mang sang bài tiếp theo

  • Map lookup có “comma ok” để biểu diễn presence.
  • Nil map đọc được nhưng không ghi được.
  • Determinism và concurrency phải được thiết kế, không tự nhiên có.
