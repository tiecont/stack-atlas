Graceful Shutdown và Process Lifecycle

Dừng nhận traffic, cancel background work và đóng dependency theo đúng thứ tự.

Deploy Kubernetes hay systemd đều có lúc process nhận SIGTERM. Nếu shutdown chỉ là os.Exit, request in-flight có thể bị cắt và data đang flush có thể mất.

1. Nhận signal

goctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
defer stop()

<-ctx.Done()

2. Dừng server với deadline

goshutdownCtx, cancel := context.WithTimeout(context.Background(), 15*time.Second)
defer cancel()
_ = srv.Shutdown(shutdownCtx)

3. Thứ tự shutdown

Ngừng nhận traffic mới → chờ request in-flight → stop producers/workers → flush telemetry → đóng DB/client resources.

4. Shutdown phải bounded

Graceful không có nghĩa chờ vô hạn. Deployment platform cũng có termination deadline.

Test nóShutdown path là code production thật. Hãy integration-test SIGTERM thay vì chỉ tin nó hoạt động.

Điểm cần nhớ

  • SIGTERM là normal lifecycle event.
  • Shutdown cần deadline.
  • Đóng dependency theo ownership/order.
Bài tập thực hànhViết integration test start server, gửi request chậm, trigger cancel và xác nhận request có cơ hội hoàn thành trước deadline.
