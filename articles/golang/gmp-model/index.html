G-M-P Model

Goroutine, Machine và Processor: mental model để hiểu scheduler sâu hơn.

Part of Golang Backend EngineeringGo Concurrency · Lesson 22

1. G-M-P là gì?

Một mental model quan trọng của Go scheduler: G là goroutine, M là OS thread, P là logical processor resource mà M cần để chạy Go code.

2. G — Goroutine

G chứa execution state của goroutine: stack, instruction position và metadata scheduler cần để pause/resume nó.

3. M — Machine

M đại diện cho một OS thread thực tế. Runtime có thể có nhiều M; một số có thể block trong syscall.

4. P — Processor

P giữ local run queue và tài nguyên cần để execute Go code. Số P thường gắn với GOMAXPROCS, tức số logical processors chạy Go code song song.

Goruntime.GOMAXPROCS(0) // đọc giá trị hiện tại

5. Work stealing

Nếu một P hết việc trong local queue, nó có thể lấy bớt runnable goroutine từ P khác. Điều này giúp cân bằng tải mà không cần một global queue duy nhất cho mọi thao tác.

Đừng overfit mental modelG-M-P giúp reasoning, nhưng scheduler implementation thay đổi theo phiên bản Go. Hãy dùng nó để hiểu nguyên lý, không dựa vào chi tiết nội bộ như contract ứng dụng.
