Runtime Toolbox: trace, GODEBUG và production diagnosis

Kết nối metrics, pprof, runtime trace và GODEBUG trước khi bước sang Go Concurrency.

1. Mental model

Runtime diagnostics của Go gồm profiling, execution trace, runtime metrics và các chế độ debug. Không có một tool duy nhất trả lời mọi câu hỏi. `pprof` tốt cho hot spots; execution trace tốt để thấy scheduling, blocking, syscalls và GC theo timeline.

`GODEBUG` có nhiều knobs/trace option, nhưng chúng là diagnostic/runtime controls có thể evolve theo release. Kiểm tra tài liệu version hiện tại trước khi dùng production.

Runtime noteNội dung runtime được viết theo Go 1.27 hiện hành. Các chi tiết implementation có thể thay đổi; language/spec behavior mới là contract ổn định.

2. Code đầu tiên

Gogo test -trace trace.out ./...
go tool trace trace.out

GODEBUG=gctrace=1 ./app
GODEBUG=schedtrace=1000 ./app

3. Hiểu sâu hơn

Execution trace giúp thấy chương trình bị serialize ở đâu, goroutine block do sync/network/syscall, GC cycle và scheduler behavior. Runtime metrics cung cấp signal liên tục tốt hơn việc bật trace dài.

Đây là cầu nối sang Season 03: một khi bạn thấy goroutine và scheduler trên timeline, concurrency không còn là abstraction mơ hồ.

Example# Mental flow
Symptom -> metrics -> hypothesis -> targeted profile/trace -> change -> re-measure

4. Khi đặt vào backend thật

Runbook production nên map symptom → metric → profile/trace. Ví dụ p99 tăng nhưng CPU thấp: kiểm tra downstream latency, goroutine blocking, connection pool, mutex contention trước khi scale CPU.

Câu hỏi nên tự hỏiKhi concept này đi qua HTTP, database, cache hoặc worker, ownership nằm ở đâu, lifecycle kết thúc khi nào, và failure được biểu diễn ra sao?

5. Sai lầm thường gặp & điều cần nhớ

Sai lầm thường gặp

  • Bật trace nặng quá lâu trên production mà không đánh giá overhead.
  • Dùng GODEBUG từ blog cũ mà không check release docs.
  • Thu hàng GB diagnostics nhưng không có hypothesis.

Điều cần mang sang bài tiếp theo

  • Diagnostics là quy trình điều tra, không phải collection tool ngẫu nhiên.
  • Phân biệt CPU hot spot, memory retention và blocking/scheduling issue.
  • Season 03 sẽ dùng mental model này để học goroutine, channel và scheduler.
