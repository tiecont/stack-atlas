Một hệ thống production cần biết từ chối có chủ đích. 429/503 nhanh thường tốt hơn để 100% request treo 30 giây rồi cùng thất bại.

1. Rate limit khác concurrency limit

Rate limit kiểm soát request theo thời gian. Concurrency limit kiểm soát số request đang in-flight. Hai thứ giải quyết hai failure mode khác nhau.

3. Per-user, per-IP hay global?

Keying strategy phụ thuộc threat model và fairness. Một global limit duy nhất có thể để một tenant chiếm hết capacity.

4. Load shedding

Khi dependency đã bão hòa, reject sớm giúp giữ latency cho phần traffic còn lại.

OverloadQueue vô hạn chỉ biến overload thành memory pressure và latency khổng lồ.

Điểm cần nhớ

  • Rate, concurrency và queue length là ba controls khác nhau.
  • Limit nên phản ánh downstream capacity.
  • Reject sớm là một reliability feature.
