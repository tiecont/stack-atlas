HTTP Client, Transport và Connection Pooling

Phần dễ bị bỏ qua nhưng quyết định latency, socket usage và độ ổn định của outbound calls.

Trong Go, http.Client là API cấp cao; http.Transport mới là nơi quản lý connection, proxy, keep-alive và nhiều network policy quan trọng.

1. Reuse Client và Transport

govar transport = &http.Transport{
    MaxIdleConns:        200,
    MaxIdleConnsPerHost: 50,
    IdleConnTimeout:     90 * time.Second,
}

var client = &http.Client{
    Transport: transport,
    Timeout:   5 * time.Second,
}

Các con số trên chỉ là ví dụ. Pool sizing phải dựa trên concurrency, số host, latency và upstream behavior.

Theo tài liệu net/httpTransport cache connections để reuse và nên được tái sử dụng thay vì tạo theo từng request. Transport cũng an toàn cho concurrent use.

2. Response body và reuse

goresp, err := client.Do(req)
if err != nil { return err }
defer resp.Body.Close()

body, err := io.ReadAll(io.LimitReader(resp.Body, 1<<20))

Đóng body là bắt buộc về resource lifecycle. Với HTTP/1.x, việc đọc body đến EOF trong các trường hợp thích hợp còn giúp connection có cơ hội reuse.

3. Pool cũng là một resource limit

Nếu service tạo outbound concurrency lớn hơn khả năng downstream, chỉ tăng connection limit có thể chuyển bottleneck sang server kia. Hãy kết hợp pool policy với timeout, bounded concurrency và rate limit.

4. DefaultClient không phải sai, nhưng explicit policy tốt hơn

Library code thường nên nhận client từ caller để test và cấu hình. Application code production thường nên khai báo client theo dependency thay vì rải http.Get khắp codebase.
