TLS và HTTPS cho Go Backend

Handshake, certificate, hostname verification và cách crypto/tls nằm giữa TCP và HTTP.

HTTPS không phải protocol hoàn toàn khác HTTP; có thể hình dung HTTP chạy trên một connection đã được TLS bảo vệ. TLS giải quyết confidentiality, integrity và peer authentication theo cấu hình/certificate.

1. TLS handshake có cost

Khi connection TLS mới được tạo, hai phía phải negotiate protocol parameters và xác thực. Connection reuse giúp tránh lặp lại toàn bộ cost này cho mỗi request.

2. Server TLS

gosrv := &http.Server{
    Addr:    ":8443",
    Handler: mux,
    TLSConfig: &tls.Config{
        MinVersion: tls.VersionTLS12,
    },
}

log.Fatal(srv.ListenAndServeTLS("cert.pem", "key.pem"))

Version policy phụ thuộc môi trường và yêu cầu bảo mật. Tránh copy cấu hình cipher/version cũ từ blog nhiều năm trước mà không hiểu default hiện tại của Go.

3. Đừng tắt verify để “fix” certificate error

go// Anti-pattern production:
TLSClientConfig: &tls.Config{InsecureSkipVerify: true}

Certificate error có thể nói hostname không khớp, chain không trusted hoặc certificate hết hạn. Tắt verification làm mất một phần quan trọng của TLS security model.

Local/devNếu dùng private CA, cấu hình trust store/RootCAs đúng cách thay vì disable verification toàn cục.

4. TLS còn tham gia protocol negotiation

Với HTTPS, ALPN có thể giúp client/server chọn HTTP/2 hoặc HTTP/1.1. Vì vậy TLS config và HTTP protocol config có thể liên quan tới nhau.
