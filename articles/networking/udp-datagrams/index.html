UDP và Datagram: Khi không có Connection

Khác biệt giữa TCP stream và UDP datagram, cùng cách dùng PacketConn trong Go.

UDP không cho bạn reliable ordered stream như TCP. Đổi lại nó có message boundary tự nhiên, overhead thấp và không cần thiết lập connection theo cách TCP làm.

1. TCP và UDP giải quyết bài toán khác nhau

TCPUDP
Ordered byte streamDatagrams
Reliability/retransmissionApplication tự quyết nếu cần reliability
Connection stateConnectionless semantics

2. UDP server trong Go

goaddr, _ := net.ResolveUDPAddr("udp", ":9999")
conn, err := net.ListenUDP("udp", addr)
if err != nil { log.Fatal(err) }
defer conn.Close()

buf := make([]byte, 2048)
for {
    n, peer, err := conn.ReadFromUDP(buf)
    if err != nil { continue }
    _, _ = conn.WriteToUDP(buf[:n], peer)
}

3. UDP thường xuất hiện ở đâu?

DNS truyền thống thường dùng UDP cho nhiều query; telemetry, game networking, discovery protocol và transport hiện đại như QUIC cũng xây trên UDP nhưng tự bổ sung semantics cao hơn.

Không phải “UDP nhanh hơn TCP”Đó là cách nói quá đơn giản. UDP cung cấp semantics ít hơn. Nếu ứng dụng tự implement retransmission, ordering, congestion control... thì complexity quay trở lại ở tầng ứng dụng.

4. Backend engineer nên học tới đâu?

Bạn không nhất thiết dùng UDP mỗi ngày, nhưng hiểu nó giúp bạn hiểu DNS, QUIC/HTTP/3 và lý do “không có connection” không đồng nghĩa “không có state ở application”.
