Khi response không kết thúc ngay: flush dữ liệu, server-sent events và bidirectional connections.

Không phải HTTP response nào cũng là JSON được tạo xong rồi gửi một lần. Go cho phép stream dữ liệu dần; từ đó ta có SSE, downloads lớn và các kiểu realtime communication khác.

1. Streaming response

gofunc stream(w http.ResponseWriter, r *http.Request) {
    flusher, ok := w.(http.Flusher)
    if !ok {
        http.Error(w, "streaming unsupported", 500)
        return
    }

    for i := 0; i < 5; i++ {
        fmt.Fprintf(w, "chunk %d\n", i)
        flusher.Flush()
        time.Sleep(time.Second)
    }
}

2. Server-Sent Events

SSE dùng HTTP response lâu dài để server đẩy text events xuống client. Nó phù hợp khi data chủ yếu đi một chiều server → browser và bạn muốn semantics đơn giản hơn WebSocket.

3. WebSocket

WebSocket tạo kênh bidirectional lâu dài và có framing riêng. Standard library Go cung cấp các primitives HTTP/network cần thiết nhưng application thường dùng một WebSocket implementation/library chuyên dụng thay vì tự viết frame protocol.

4. Long-lived connection cần lifecycle rõ ràng

  • Heartbeat/idle policy.
  • Backpressure khi client đọc chậm.
  • Cancellation khi client disconnect.
  • Connection limit và memory per connection.
  • Graceful shutdown.
Realtime không chỉ là syntax10.000 connection idle và 10.000 connection đẩy 100 message/s là hai workload hoàn toàn khác nhau. Capacity planning phải dựa trên traffic thật.
